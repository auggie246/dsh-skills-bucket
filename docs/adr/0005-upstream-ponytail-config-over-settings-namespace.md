# Upstream ponytail config over a settings namespace

The bundle resolves ponytail's default mode with the upstream hook contract — the `PONYTAIL_DEFAULT_MODE` environment variable, then `defaultMode` in the ponytail config file (`XDG_CONFIG_HOME`, then `%APPDATA%` on Windows, then `~/.config`), then `full` — at host start, and adapts the vendored `ponytail` skill at registration: a non-full level is written into the body's two default markers, `off` skips the mode skill, `full` registers verbatim. The rejected alternative: a DSH settings namespace with a card under Settings > Plugins — the Plugins page renders a served namespace only when a registered browser card claims it, so that path needs a schemastery schema, a client half, and a keyed `settings.plugin.item` card; too much machinery for one preference. Trade-offs: the rewrite matches three literal markers from ponytail v4.9.0, so an upstream rephrase no-ops (apply() warns about the drift instead of failing); changes apply on harness restart, like every bundle update; and a config file written for another host's ponytail install drives this one too, which is the point.
