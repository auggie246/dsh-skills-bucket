# Runtime registration over file copy for bundled skills

The plugin bundle registers each skill directly on the skill registry (`ctx.skills.register`) at host start. The rejected alternative was the dsh-mcp-adapter pattern: copy each `SKILL.md` into `$DSH_HOME/skills/` and let the filesystem provider discover it. Runtime registration keeps the package the single source of truth — a package upgrade replaces the skills on restart, and removing the package removes them — and it avoids shadow copies that drift from the repo. The trade-off: runtime entries outrank same-named user-directory copies, so a skill in this package cannot be overridden by editing `$DSH_HOME/skills/`; and updates reach agents only after a harness restart, since the plugin code runs inside the host process.
