# Source precedence for combined skills

Skills in this repo often combine several upstream sources that can disagree. When they conflict, the rule is: scope bans from a task-style source (for example, an awesome-copilot prompt) win over a structural spec — banned sections such as License, Contributing, and Changelog are never written. A structural spec (for example, standard-readme) governs everything else — section titles, order, per-section content — with its own applicability conditions kept intact (Install/Usage optional for documentation repositories, API for libraries). The rejected alternative was to let the spec win strictly; that would force License and Contributing sections into every generated README, contradicting the convention that those live in dedicated files.
